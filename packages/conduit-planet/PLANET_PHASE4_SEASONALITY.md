# Conduit Planet – Phase 4 Seasonality

## Status

`climate.seasonality` now has a canonical simulation-time-driven seasonal path.

The migration deliberately separates the slow orbital season cycle from the fast weather animation clock.

## Time source

The game simulation epoch is:

```text
3030-01-01T00:00:00Z
```

`SimulationClock.elapsedSeconds` is the only elapsed-time input used to derive orbital/season phases.

`PlanetDefinition.orbit.orbitalPeriod` is generated by Kepler-style `sqrt(a^3)` and is expressed in Earth-year units. The simulation conversion is therefore:

```text
periodSeconds
= orbitalPeriod
* 365.25 days
* 24 h
* 60 min
* 60 s
```

`src/game/simulation/PlanetSeasonCycle.ts` owns this conversion and returns a normalized phase in `[0, 1)`.

The epoch is only an unnamed phase-zero reference. Phase 0 is intentionally not called winter, spring, periapsis, etc. A future orbital-position model may add a deterministic phase offset.

## Seasonal weather layer

The static/fast canonical weather evaluator stays unchanged:

```text
getWeatherSample(normal, climate, weatherTime, definition)
```

A new wrapper adds slow seasonality:

```text
getSeasonalWeatherSample(
    normal,
    climate,
    weatherTime,
    definition,
    seasonPhase,
)
```

The seasonal signal is hemispheric and continuous:

```text
seasonalWave = sin(seasonPhase * 2π)
hemisphereWeight = normal.y
seasonalStormBias = seasonalWave
                  * hemisphereWeight
                  * climate.seasonality
                  * 0.18
```

North and south therefore receive opposite seasonal storm tendency at the same orbital phase, while the equatorial response approaches zero.

## Ownership / invariants

Seasonality currently affects only dynamic weather response:

- `stormPotential`
- downstream `cloudBoost`
- downstream `swirl`

It does not change:

- pressure topology
- low/high-pressure masks
- weather seed identity
- wind bands
- global wind strength
- canonical static `ClimateSample`
- terrain geometry
- terrain collision / landing
- land/water classification

`seasonality = 0` is neutral and reproduces the base weather sample.

## Intentionally deferred

Dynamic seasonal temperature, snow/ice coverage, vegetation/biome state and surface-material changes are not implemented in this step.

Those require a separate seasonal-climate/material layer. `PlanetTerrainSampler` must remain deterministic and geometry-safe rather than becoming dependent on continuously advancing game time.

## Tests

`packages/conduit-planet/tests/PlanetSeasonality.test.ts` covers:

- pressure/wind invariance across seasons
- opposite hemispheric seasonal tendency
- neutral behavior when `seasonality = 0`
- deterministic phase wrapping

`tests/PlanetSeasonCycle.test.ts` covers:

- Earth-year conversion of `orbitalPeriod`
- phase derivation from `SimulationClock`
- planet-specific orbital periods
- phase-zero epoch semantics

Both suites are blocking CI inputs.
