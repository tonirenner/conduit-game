# Conduit Planet – Regional → Surface handoff finding

Status: observed / documented, not fixed

## Symptom

The current RegionalView → SurfaceView transition is visibly discontinuous in motion.

Observed behaviour from the captured approach video:

- Regional terrain keeps a relatively smooth, bright, low-detail appearance.
- Surface terrain fades in with a materially different response and noticeably stronger local detail.
- During the overlap the two representations do not visually read as the same surface at two LODs.
- Near the end of the handoff the image changes abruptly instead of completing as a seamless blend.

This is a renderer handoff issue, not a canonical terrain-height mismatch.

## Primary cause 1 – Regional and Surface do not share material semantics

`CurvedRegionalTileTerrain` currently uses a deliberately minimal `THREE.MeshStandardMaterial`:

```text
vertexColors = true
metalness = 0
roughness = 0.9
```

Its vertex color is generated by a separate class-only palette in `resolveTerrainColor()`.

It does not consume the active Surface material semantics that now include:

- continuous composition influences,
- canonical ice-cap shading,
- canonical volcanic mask shading,
- water composition response,
- toxic / metal / rock / organic material response,
- micro normals,
- cavity AO,
- detailed roughness/metalness variation.

`SurfaceClipmapTerrain`, in contrast, uses `evaluateSurfaceTerrainMaterial()` plus the WebGPU node material detail path.

Therefore the Regional → Surface handoff currently blends two different materials, not just two geometry resolutions.

## Primary cause 2 – Regional is released with a hard visibility switch

`PlanetViewRuntime` intentionally keeps Regional fully opaque during the Regional → Surface overlap:

```ts
const regionalOpacity = weights.surface > 0.001
    ? 1
    : weights.regional;
```

Then Regional is hidden when Surface reaches the depth-ownership threshold:

```ts
if (weights.surface >= 0.985) {
    regional.group.visible = false;
}
```

This avoids exposing the finite Surface clipmap horizon while Surface is still only a local patch, but it also means the final transition is not a true crossfade.

At `surfaceWeight ~= 0.985`, the complete Regional representation disappears in one frame.

If Regional and Surface differ in color, roughness, normals, local detail, exposure response, or geometry sampling density, this switch becomes visible as a pop.

## Secondary contributor – different detail scales

Regional terrain is geometry-first and intentionally minimal in material detail. SurfaceView adds high-frequency fragment detail and local tangent-space shading.

Even with identical broad albedo, the sudden appearance of:

- micro-normal detail,
- cavity response,
- fragment-scale roughness variation,
- stronger local composition features

can make the transition read as a texture/material swap.

## What is probably NOT the root cause

Both Regional and Surface geometry ultimately use the canonical `PlanetTerrainSampler`.

So the first diagnosis should not be "two different terrain generators".

The dominant mismatch is currently rendering/material ownership and the handoff policy.

## Current handoff band

```text
regionalSurfaceStartMeters = 90_000
regionalSurfaceEndMeters   = 20_000
surfacePreloadMeters        = 140_000
surfaceReleaseMeters        = 220_000
surface depth ownership     = 0.985
```

Surface fades in across roughly 90 km → 20 km altitude, while Regional remains fully opaque beneath it until the Surface weight reaches 0.985.

## Recommended direction for a later fix

Do not start by merely widening the transition band.

First make Regional and Surface agree on broad material semantics:

```text
same canonical terrain sample
+ same broad surface-material evaluation
+ different detail budget per view
```

Regional should ideally use the same broad albedo / roughness / metalness ownership as Surface, while omitting only expensive near-field micro detail.

After the broad materials match, revisit the ownership transition so Regional can release progressively or through a spatial/depth-aware handoff instead of one global visibility cut.

Potential target architecture:

```text
Canonical Surface Material Evaluation
├─ Orbit: low-frequency / cheap representation
├─ Regional: broad material + medium detail
└─ Surface: broad material + near-field micro detail
```

The three views should differ in detail frequency and geometry budget, not in the underlying material identity.

## Safety constraints for the eventual fix

Do not change as part of this handoff repair unless proven necessary:

- canonical terrain heights,
- landing/collision,
- atmosphere reconstruction,
- camera/reference-frame logic,
- regional seam stitching,
- Surface clipmap topology.

The first repair should stay in material continuity + renderer ownership.
